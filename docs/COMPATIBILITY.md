# 兼容性与硬件验证矩阵

本文区分“代码支持”和“真实硬件已验证”。自动化测试通过不代表飞行安全，也不能替代拆桨条件下的硬件在环验证。

状态定义：`已验证` 表示维护者按本文流程留下了可追溯记录；`代码支持，待实机` 表示已有对应协议或连接实现，但尚无公开硬件证据；`不支持` 表示当前没有实现。

## 当前兼容范围

| 项目 | 状态 | 说明 |
|---|---|---|
| PX4 MAVLink v1 | 代码支持，待实机 | 编解码器支持 v1 framing 与 CRC |
| PX4 MAVLink v2（未签名） | 代码支持，待实机 | 默认协商路径 |
| PX4 MAVLink v2 signing | 代码支持，待实机 | 支持签名、重放窗口及 require-signed 配置 |
| USB 串口（Windows / Linux / macOS） | 代码支持，待实机 | 基于 `serialport`；平台命名和权限仍需逐机验证 |
| Windows Bluetooth SPP | 代码支持，待实机 | 优先匹配可打开的 outgoing COM 端口，不把 incoming 端口标为可用 |
| UDP / PX4 SITL | 不支持 | 属于中期路线 |
| Chrome / Edge Web Serial 设备选择 | 代码支持，待实机 | 需要 HTTPS 或 localhost；后端最终负责打开 COM 端口 |

## 最小硬件验证流程

1. 移除螺旋桨，记录飞控型号、PX4 完整版本、系统版本、连接类型和波特率。
2. 验证扫描、连接、心跳就绪、完整参数下载、断开和物理拔插后的重连。
3. 验证遥测、参数写入回显，以及加速度计/陀螺仪/磁力计校准提示。
4. Bluetooth SPP 需额外确认 incoming/outgoing COM 识别、断链、自动重连和长时间稳定性。
5. 仅在受控环境中验证电机、解锁、模式和手柄；保留人工急停/接管能力。
6. 使用 Bug 模板提交结果或问题，上传前对日志中的位置、设备标识、token 和 signing 信息脱敏。

每次验证应明确写出未覆盖项。失败结果同样有价值，不应从矩阵中删除。
